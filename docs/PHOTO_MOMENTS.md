# 旅行中的拍照瞬间

出门时核心会排入一次 `photo-idea` 文字任务。QQ 适配器在聊天空闲时，请现有文字模型结合目的地、意愿、预计北京时间、可用天气、实际背包和最近五张照片，构思最多三个不同瞬间。每个瞬间包含具体事件、姿态、表情、镜头和相册短句；活动类别只用于规则校验，事件文字可以自由创作。

拍照发生时，核心使用当时的时间、可靠天气和出门时冻结的衣服、食物与背包筛选建议。未知天气采用室内或遮蔽场景，雨雪检查雨伞，雷雨避免室外，不吃饭时不拿便当。最近五张的动作类别、姿态和镜头组合不重复，上一张表情也参与筛选。程序无法从自然语言完全理解姿态，因此生成结果仍可能有细节偏差。

模型繁忙、超时、JSON 无效、建议过晚或不符合条件时，不等待它补写，也不阻塞回家与出图；改用多组事件、手势、视角和表情组合。没有强制每次调用模型或追求固定动作。一次文字规划失败不会自动连续重试。

最终事件在首次拍照时冻结。绘图重试、更换绘图后端、相册文案都使用同一事件，不能在晚上重试时把下午的照片改成夜景。已有照片不重新生成。

更新游戏核心后，也需要更新聊天仓库的游戏适配器、模型请求参数透传和 `room-settings.mjs`：规划最多使用 1400 个输出 token，普通聊天保持原默认值。仅更新核心时会使用安全的多样化备用场景。

验证：`node --test tests/photo-scenes.test.mjs`。测试使用内存存档、模拟文字回复，不生图、不发 QQ、不改真实旅行。
